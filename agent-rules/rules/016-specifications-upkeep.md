# 016 — Keeping specifications current

The knowledge base is the memory of the project. An agent forgets everything between sessions; the
developer, the team and other sessions cannot see an agent's memory. Everything that matters
goes into `specifications/` in the same task as the code.

## What to update when

| Change | Update in the same task |
|---|---|
| Any work (feature, fix, review, refactoring) | `logs/YYYY-MM-DD-<topic>.md`, registry `status` and `progress_percent`, `product/CHANGELOG.md` |
| Behaviour of an endpoint or a flow | the task spec, the API contract, test document, `TEST_COVERAGE.yaml` |
| New or changed requirement from the tracker | `product/source-tasks/<id>.md` (new text verbatim, old kept), registry criteria with `[<TRK>-<id>]`, spec |
| Question to the client or a decision of the developer | `questions/OPEN_QUESTIONS.md`; when answered — decisions table and the affected criteria with `[Q-NN]` |
| Architecture or design decision | a new ADR in `architecture/adr/`, `architecture/SYSTEM_OVERVIEW.md` |
| Database schema | `architecture/SYSTEM_OVERVIEW.md` (data model section), migration |
| Partner or tracker behaviour observed in a real response | `integrations/<SYSTEM>.md`, "Real API findings" |
| Personal data stored or sent | `security/PERSONAL_DATA.md` |
| Defect found | `bugs/BUGS.md` and a criterion `[BUG-NNN]` in the affected task |
| New or renamed spec or test document | `python3 agent-rules/scripts/gen_spec_index.py` |
| Registry, `product/source-tasks/README.md` or `questions/OPEN_QUESTIONS.md` | `python3 agent-rules/scripts/gen_project_review.py` (skill `project-review`); with required translations first the Russian texts in `specifications/i18n/PROJECT_REVIEW.ru.yaml` (`--missing`) |
| `AGENTS.md` or a project rule in `agent-rules/rules/` | `python3 agent-rules/scripts/gen_rule_index.py`, then `python3 agent-rules/scripts/gen_cursorrules.py` |
| A managed file (core or stack rule, script, hook, shared skill) needs a change | nothing here: propose the change in the boilerplate repository (`019-rule-layers-and-updates.md`) |

## Rules

- **016.1** Update `specifications/` in the same task as the code; "later" does not happen.
- **016.2** Say "added a task" or "recorded the decision" only after it is in the files.
- **016.3** An agent's own memory is not a substitute for `specifications/`: write to the files
  first, memory last and only as a supplement.
- **016.4** Question numbers: next after the maximum in the Open section and the decisions
  table; bug numbers: next after the maximum in `BUGS.md`. Re-read the file right before writing.
- **016.5** Every work log starts with the plan (sources, decisions, how it will be checked)
  written before coding, then "Done", "Checks" (gate per step), "Code review" (date, separate
  session), "Statuses", "Findings and decisions".
- **016.6** Developer decisions are recorded with a date and a source.
- **016.7** An ADR is never rewritten: a changed decision gets a new ADR that supersedes the
  old one, and the old ADR is marked as superseded.

## Enforcement

- **016.8** The gate fails when code (`CODE_PATHS` in `agent-rules/project.sh`, minus
  `SPEC_EXEMPT_PATHS`) changed in the working tree but nothing under `specifications/` did
  (`agent-rules/scripts/spec_freshness.sh`).
- **016.9** The Claude Code Stop hook (`.claude/settings.json`) runs the same check and asks the
  agent once to update the specifications before finishing; if no update is needed, the agent
  states why in the work log.
- **016.10** The gate validates the registry, labels, coverage, questions, bugs, links and the
  spec index (`agent-rules/scripts/check_specs.py`, `gen_spec_index.py --check`).
- **016.11** `.cursorrules` is generated from `AGENTS.md` and `agent-rules/rules/` for Cursor and
  any pipeline that reads one rules file, and the rule index in `AGENTS.md` is generated from the
  rule files. Never edit either by hand: after changing the rules run
  `python3 agent-rules/scripts/gen_rule_index.py` and
  `python3 agent-rules/scripts/gen_cursorrules.py`; the gate fails when either is stale.
- **016.12** `specifications/PROJECT_REVIEW.html` shows the team and stakeholders the state of the
  project: tasks with status and readiness, open questions and decisions. It is generated by
  `agent-rules/scripts/gen_project_review.py` (Claude Code skill `.claude/skills/project-review/`);
  never edit it by hand. The page switches between English and Russian; Russian texts of the data
  live in `specifications/i18n/PROJECT_REVIEW.ru.yaml`. With `project.review_translation: required`
  in the registry the gate fails when a translation is missing or unused; otherwise missing texts are
  shown in English. The gate always fails when the page is stale.
