# 017 — Communication and reports

- **017.1** All project files — rules, specifications, code comments, commit messages, work
  logs — are written in English. The chat language with a person follows that person's own
  instructions.
- **017.2** Be direct, practical and precise; do not hide uncertainty. Express status through
  facts ("Gate: failed", "Status: blocked", "Reason: …", "Next action: …"), without rhetorical
  sincerity markers ("honestly", "frankly", "to be honest").
- **017.3** Every ID mentioned to a person (task, bug, question, ADR, tracker task) is written as
  "[ID] — title", with the title taken from the project source. This applies to every mention.
- **017.4** For non-trivial technical choices state the chosen approach, the main alternative
  and why the chosen one is safer.
- **017.5** Final report of every task: repository sync (fetched, pulled, code changed,
  blocked and why); what was changed or found; files changed or inspected; verification performed
  (gate per step); remaining risks and follow-ups.
- **017.6** Use clear headings, short bullets and concrete file and function references; do
  not use the middle dot character (U+00B7) as a separator.
- **017.7** If access is missing (repository, registry, partner environment, task tracker, a file),
  say so immediately: what is missing, why it is needed and how to grant it.
- **017.8** Do not ask again about decisions the developer has already made; they are recorded in
  `questions/OPEN_QUESTIONS.md`.
